# How BM25 ranks

A search engine with no idea what words mean. It counts them, weighs the rare
ones more, and divides by how much was written — and that is the whole of it.
Every number on this page came from scoring your query against the real
catalogue just now.

## 2. What the words are worth

Before any phone is looked at, each word is priced by how many records contain
it. A word in almost every record can barely separate them; a word in a handful
does most of the work. This is a fact about the catalogue, so it is the same
for every row below.

## 3. What actually ranks

{% if not e.rows %}
Nothing. Not one record in the catalogue contains a single one of those words,
so there is nothing to rank and nothing to explain — the sections below need a
score to work from. This is the blunt version of the failure the last section
draws out at length: BM25 can only return documents that share a token with
what you typed.

{{ ui.ranked_table(e, link) }}

Presence and rank are two different mechanisms. Every row here contains at
least one query word — that is membership. What orders them is how often the
word appears and how long the record is.

{% if e.pair %}
Read the `{{ e.pair.token }}` column for **{{ e.pair.shorter.name }}** and
**{{ e.pair.longer.name }}**. Same word, same weight, said {{ e.pair.tf }} times in
both — {% if e.pair.shorter_score > e.pair.longer_score -%}
and it is worth {{ "%.2f"|format(e.pair.shorter_score) }} to the first and
{{ "%.2f"|format(e.pair.longer_score) }} to the second. The only thing separating
them is {{ e.pair.shorter.length }} tokens against {{ e.pair.longer.length }}:
BM25 divides by length, so a padded record cannot win by being wordy.

and worth exactly the same to each, though one runs {{ e.pair.shorter.length }}
